# Disciplinary Committee (discom)

Russian-language HR portal (СПбГУ): directories, documents, ledgers and a
report are separate Go microservices, each backed by its own Postgres, fronted
by Traefik, with a vanilla-JS "protofront" desktop shell plus a React/Vite app.

## Repo map

- `source/{directory,document,ledger,report}/ms_<name>/` — one Go module per
  entity (module name `ms_<name>`). Layout per service:
  `main.go`, `model/model.go`, `parameters.env`, `dbshell/db.sh`,
  `system_description/{01,02,03}*.sql`, `system_description/compose_part.yaml`.
- `source/shared/` — shared Go lib (`app`, `config`, `controller`, `sys`); imported
  as module `shared` via `go.work`. Each entity's `main.go` is ~10 lines:
  `app.App[model.Object]` → `CreateConnection()` + `CreateRoutes()`.
- `source/directory/ms_system_object_directory/` — metadata service that drives
  the whole UI (menu, forms, workflows). Its `dbshell/db.sh` is **generated** by
  `build-db.sh`; edit `dbshell/db.sh.base` and the per-entity
  `system_description/*.sql`, not the generated file.
- `protofront/` — vanilla-JS desktop shell served by nginx as container
  `frontend-js` (the live front at `https://discom.spbgu.localhost:8443/`).
- `frontend/` — React + Vite + Vitest + Playwright app (newer, partially wired).
- `Dev_tools/entity_manager/` — Flask scaffolder that generates new Go modules,
  `db.sh`, `parameters.env`, `Dockerfile`, compose and inserts.
- `Dockerfiles/` — per-service Dockerfiles generated by `refresh_dockerfile.sh`
  from `Dockerfile.work`.
- Root scripts: `build-compose.sh`, `build-db.sh` (under the metadata service),
  `pre-compose.sh`, `refresh_dockerfile.sh`, `pre_traefik.sh`.

## Service model

- Every entity is a Go module (`ms_<name>`) exposing REST at
  `/api/<tablename>` (Traefik `PathPrefix`), backed by Postgres on the `vnet`
  bridge network `172.25.0.0/24`. Postgres containers listen on `172.25.0.x:5434`.
- `parameters.env` carries `DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_TABLENAME/APP_PORT`.
- Postgres init scripts mount `dbshell/` → `/docker-entrypoint-initdb.d/`, so a
  schema/seed change only applies after **re-initializing the DB volume**.
- The metadata service (`ms_system_object_directory`, `DB_TABLENAME=system_object_directory`)
  is the single source the front queries to build menus and forms.

## Conventions

- Group build order is fixed: `directory → document → ledger → report`
  (alphabetical within a group), and mirrored for compose and DB seeds.
- Naming: groups `*_directory`, documents `*_document`, ledgers `*_data_ledger`,
  report `job_report`; per entity `object_link.path` equals the DB tablename.
- Russian comments/strings throughout; keep them in Russian.
- Do not hand-edit `docker-compose.yaml` (gitignored) or `dbshell/db.sh`; use
  `build-compose.sh` and `build-db.sh`.

## Which skill to load

- Editing `system_description` SQL, seeds, `db.sh.base`, or adding an entity →
  `dc-system-object-schema`.
- Building/running/debugging the stack, podman, Traefik, Postgres access,
  headless browser → `dc-stack-ops`.
- protofront shell or React app, API contract, UI pipeline → `dc-frontend`.
